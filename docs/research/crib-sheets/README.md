# Crib Sheets

Reference docs for vanilla Railroader internals, written for modders who need to know "is there a patch point for X" without re-decompiling. Companion to the narrative `../*-vanilla-survey.md` documents.

## How crib sheets differ from surveys

- **Surveys are narratives.** They explain how a system thinks. Read once, absorb the model.
- **Crib sheets are references.** They list types, signatures, and patch candidates. Skim with ctrl-F.

If a fact appears in both, the survey wins on *why* and the crib sheet wins on *where*.

## Format conventions (established by the wear-durability + couplers pilot pair)

Every crib sheet follows this shape:

1. **Header**: title, date, source-of-truth path, companion-doc link(s).
2. **One-paragraph context**: what the system does, why a modder cares.
3. **"Key entry points at a glance"**: 5–8 row table of the most important types/methods, file path, one-line role. The fast-jump index.
4. **Spine section**: a structural backbone unique to the topic (e.g., the `WearFeature` toggle propagation chain). Lays out the shape before the per-type details.
5. **Per type/component sections** with consistent sub-structure:
   - Fully-qualified name in heading.
   - One-or-two-sentence domain description.
   - Code-block signatures with `// file:line` citations.
   - **Patch candidates** table — method, why-patch rationale.
   - **MP authority** notes — HostOnly? Request message? KVO key auth?
   - **Related Messenger / KVO events** if applicable.
   - **Gotchas** — timing, init order, dead code, things that surprise.
6. **Cross-references** to other crib sheets via relative markdown links (`[other section](other-doc.md#anchor)`).

## Citation discipline

- Cite `file:line` for any non-obvious claim. Decompiled output line numbers are stable per-decompile-pass; if the docs are regenerated, line numbers may shift but file/method anchors won't.
- Quote code in fenced blocks for load-bearing details (formulas, thresholds, validation logic). Don't paraphrase what the source already says clearly.
- High-value findings (toggle bypasses, dual code paths, hidden gates) get **bold call-outs**.

## Scope per sheet

One coherent system per sheet. Cross-cutting concerns (e.g., a method that lives in wear but is triggered by couplers) get a primary home and a cross-reference from the other doc. Don't duplicate; link.
